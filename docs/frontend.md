# Frontend

The frontend is a Hugo static site using the Adritian theme. It lives in `frontend/`.

## Source Layout

Important paths:

- `frontend/hugo.toml` controls Hugo configuration, menus, modules, SEO settings, and theme parameters.
- `frontend/content/` contains Markdown content.
- `frontend/layouts/` contains project-level layout overrides.
- `frontend/assets/` contains theme-aware assets such as CSS and images.
- `frontend/static/` contains files copied directly into the generated site.
- `frontend/static/js/visitor-count.js` contains the visitor counter browser code.
- `frontend/layouts/partials/footer.html` renders the visitor counter element.

## Do Not Edit frontend/public Directly

`frontend/public/` is generated by Hugo. It is build output, not source code.

The correct workflow is:

```text
Edit frontend source
-> Run Hugo
-> Hugo generates frontend/public/
-> Deploy contents of frontend/public/
```

If a file in `frontend/public/` needs to change, update the source file that generated it.

## Run Locally

```bash
cd frontend
npm ci
hugo server
```

Open:

```text
http://localhost:1313/
```

`npm ci` installs the frontend dependencies used by the theme. Hugo Modules also use Go to resolve the Adritian theme module.

## Build

```bash
cd frontend
hugo --minify
```

The build writes static output to:

```text
frontend/public/
```

## Visitor Counter Integration

The visitor counter markup is in the footer:

```html
<span id="visitor-count">--</span>
```

The script at `frontend/static/js/visitor-count.js` chooses the API URL based on the current hostname:

- Local site: `http://localhost:7071/api/visitor-count`
- Production site: `https://func-crc-prod.azurewebsites.net/api/visitor-count`

If the API call succeeds, the footer displays `visitor_count` from the JSON response. If the call fails, the page leaves a safe fallback display instead of breaking the site.

## Deployment To Azure Storage

Azure Storage hosts generated static files only. The deployment target is the special `$web` container.

The important rule is to upload the contents of `frontend/public/`, not the `public` folder itself.

Correct result:

```text
$web/index.html
$web/css/
$web/js/
$web/img/
```

Wrong result:

```text
$web/public/index.html
```

The frontend GitHub Actions workflow builds Hugo, clears the existing `$web` contents, uploads the new generated output, and smoke tests the Azure Storage static website endpoint.

## Common Troubleshooting

- If Hugo cannot find theme assets, run `npm ci` and confirm Go is installed.
- If local pages load but styles are missing, check `frontend/hugo.toml` module mounts and theme dependencies.
- If the visitor counter shows `--`, check that the backend is running locally or that the production Function App is reachable.
- If the browser shows a CORS error, confirm the Function App allows the site origin.
- If an old page still appears after deployment, clear or bypass Cloudflare cache and confirm the `$web` container was updated.
